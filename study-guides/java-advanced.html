📌 JGrasp Workbench & Viewers
🔭 Object Viewers & the Workbench
JGrasp's Workbench is an interactive panel that allows you to instantiate objects, call methods, and inspect their state in real time — without writing a main method. The Object Viewer renders a live visual representation of objects and data structures (arrays, linked lists, trees) as your program runs. This is particularly powerful when learning how data structures behave internally during execution.
💡 Example: You can drag a Student object into the Workbench, call its getName() method, and see its field values update live in the viewer — all interactively.

⚙️ JGrasp Compiler Settings & Flags
S1
Compiler: javac with Debug Flag -g
JGrasp compiles Java source using javac with the -g flag by default. This flag instructs the compiler to include full debug information (variable names, line numbers, source file name) in the .class file — essential for the debugger to show meaningful variable names rather than memory addresses.
💡 Without -g, the debugger can still run but local variable names are lost.
S2
Run Arguments & VM Arguments
JGrasp allows you to pass command-line arguments to your program via Run → Run Arguments. These are passed as the args array in main(String[] args). You can also set JVM arguments (e.g., heap size: -Xmx512m) via Settings → Compiler Settings.
S3
UML Class Diagram Generation
JGrasp can automatically generate a UML Class Diagram from your source files. Navigate to Tools → Generate → UML Class Diagram. This shows all classes, their fields, methods, and relationships (inheritance, association) — extremely useful for understanding object-oriented program structure at a glance.
💡 UML = Unified Modelling Language — the standard notation for visualising OOP designs.

🐛 The JGrasp Debugger — In Depth
📌 Breakpoints, Stepping & Watch Expressions
🐛 What the Debugger Does
The JGrasp debugger allows you to pause program execution at any line, inspect the current value of every variable in scope, trace the method call stack, and step through code one line at a time. It is the most powerful tool for finding and fixing logic errors (bugs) that do not cause compile errors but produce incorrect results.
💡 Key distinction: The compiler finds syntax errors (compile-time). The debugger helps find logic errors (runtime) — where the program runs but produces the wrong output.
Debug ControlJGrasp Button / ShortcutWhat It Does
Breakpoint Click left margin of line Marks a line where execution will pause automatically
Resume ▶ Resume button Continues execution until the next breakpoint or program end
Step Over → Step Over Executes the current line; if it calls a method, executes the entire method as one step
Step Into ↓ Step Into Steps INTO a called method, pausing at its first line
Step Out ↑ Step Out Finishes the current method and returns to the calling method
Watch Expression Debug tab → Watch Monitors a specific variable or expression continuously as code executes
Call Stack Debug tab Shows the chain of method calls that led to the current execution point
🔎 Types of Errors in Java
E1
Syntax Error (Compile-Time Error)
Violates Java's grammar rules — detected by javac before the program runs. The program cannot compile until fixed.
int x = 5 // ← Missing semicolon — SYNTAX ERROR
E2
Runtime Error (Exception)
Occurs while the program is running. The program compiles fine but crashes during execution, throwing an Exception.
int[] arr = new int[5]; arr[10] = 99; // ← Index 10 doesn't exist → ArrayIndexOutOfBoundsException
E3
Logic Error (Semantic Error)
The program compiles and runs without crashing but produces incorrect results. These are the hardest errors to find and require careful debugging.
// Intent: calculate area of rectangle int area = length + width; // ← Should be * not + — LOGIC ERROR
⚠️ The JGrasp debugger is most useful for tracking down logic errors.
Section 3
🔀 Control Structures
📌 Selection & Iteration — Advanced Detail
①
if / else if / else — Selection
Selection.java int score = 75; String grade; if (score >= 90) { grade = "A"; } else if (score >= 80) { grade = "B"; } else if (score >= 70) { grade = "C"; // ← This branch executes (score = 75) } else if (score >= 60) { grade = "D"; } else { grade = "F"; } System.out.println("Grade: " + grade); // Output: Grade: C
②
switch Statement — Multi-branch Selection
More efficient than a long if-else chain when comparing one variable against many specific values. Each case must end with break to prevent fall-through (executing subsequent cases).
SwitchDemo.java int day = 3; switch (day) { case 1: System.out.println("Monday"); break; case 2: System.out.println("Tuesday"); break; case 3: System.out.println("Wednesday"); break; default: System.out.println("Invalid day"); } // Output: Wednesday // Remove 'break' after case 3 → "Wednesday" AND "Invalid day" would both print (fall-through!)
③
Three Types of Loops — When to Use Each
Loops.java // ── for loop: use when the number of iterations is KNOWN ────────── for (int i = 0; i < 5; i++) { System.out.print(i + " "); // Output: 0 1 2 3 4 } // ── while loop: use when iterations depend on a CONDITION ───────── int count = 0; while (count < 3) { System.out.print(count + " "); // Output: 0 1 2 count++; } // ── do-while loop: executes AT LEAST ONCE before checking ───────── int x = 10; do { System.out.println("Runs once even though x > 5"); } while (x < 5); // condition is false but body ran once! // ── for-each loop: iterates over arrays/collections cleanly ─────── int[] scores = {80, 90, 75}; for (int s : scores) { System.out.print(s + " "); // Output: 80 90 75 }
⚠️ Common Loop Pitfall — Off-By-One Error: Using i <= 5 vs i < 5 changes the number of iterations from 6 to 5. Always trace through your loop boundary conditions carefully.
⚠️ Infinite Loop: Forgetting to increment the counter (e.g., count++) inside a while loop causes it to run forever. JGrasp will appear to hang — use the Stop button (■) to terminate it.

📌 Method Anatomy, Overloading & Scope
MethodsDemo.java public class MethodsDemo { // ── Static method: returnType methodName(paramType paramName) ── public static int add(int a, int b) { return a + b; // returns an int value to the caller } // ── void method: no return value ─────────────────────────────── public static void printGreeting(String name) { System.out.println("Hello, " + name + "!"); } // ── Method OVERLOADING: same name, different parameters ──────── public static double add(double a, double b) { return a + b; // Java picks correct version based on argument types } public static void main(String[] args) { int r1 = add(3, 4); // calls int version → 7 double r2 = add(3.5, 2.1); // calls double version → 5.6 printGreeting("Alice"); // Hello, Alice! System.out.println(r1 + " " + r2); } }
ConceptDefinitionExample
Parameter Variable declared in the method signature (receives data) int a in add(int a, int b)
Argument Actual value passed when calling the method 3 and 4 in add(3, 4)
Return type The data type of the value the method sends back int — the method returns a whole number
void Keyword meaning the method returns nothing public static void printGreeting()
Overloading Multiple methods with the same name but different parameter lists add(int,int) and add(double,double)
Scope Where a variable is accessible — limited to the block it was declared in A variable declared inside a loop only exists inside that loop
⚠️
Pass by Value in Java
Java is strictly pass-by-value. When you pass a primitive to a method, a copy of the value is passed. Changing the parameter inside the method does NOT affect the original variable.
public static void doubleIt(int x) { x = x * 2; // changes the LOCAL copy only } int num = 10; doubleIt(num); System.out.println(num); // Still prints 10 — original unchanged!
⚠️ Reference types (objects/arrays) pass the reference by value — the object CAN be modified but not replaced.

📐 Arrays — Declaration, Traversal & 2D Arrays
📌 Arrays In Depth
📐 What is an Array?
An array is a fixed-size, ordered collection of elements that are all of the same data type. Arrays are stored in contiguous memory and accessed via a zero-based index. Once created, the size of an array cannot be changed. In JGrasp, the Object Viewer renders arrays visually as indexed boxes, making it easy to see element values during debugging.
💡 Index starts at 0, not 1. An array of size 5 has indices 0, 1, 2, 3, 4. Accessing index 5 throws an ArrayIndexOutOfBoundsException.
ArraysDemo.java // ── Declaration & Initialisation ───────────────────────────────── int[] scores = new int[5]; // creates array of 5 ints, all default to 0 int[] marks = {85, 92, 78, 90, 88}; // initialiser list — size inferred = 5 // ── Accessing elements ──────────────────────────────────────────── System.out.println(marks[0]); // 85 (first element) System.out.println(marks[4]); // 88 (last element) System.out.println(marks.length); // 5 (number of elements) // ── Traversal with for loop ─────────────────────────────────────── int total = 0; for (int i = 0; i < marks.length; i++) { total += marks[i]; } double average = (double) total / marks.length; System.out.println("Average: " + average); // 86.6 // ── Enhanced for-each loop ──────────────────────────────────────── for (int m : marks) { System.out.print(m + " "); // 85 92 78 90 88 } // ── Sorting with Arrays utility class ──────────────────────────── java.util.Arrays.sort(marks); System.out.println(java.util.Arrays.toString(marks)); // Output: [78, 85, 88, 90, 92]
📐 2D Arrays
TwoDArrays.java // ── 2D Array: array of arrays (rows × columns) ─────────────────── int[][] grid = new int[3][4]; // 3 rows, 4 columns int[][] matrix = { {1, 2, 3}, {4, 5, 6}, {7, 8, 9} }; System.out.println(matrix[1][2]); // row 1, col 2 → 6 System.out.println(matrix.length); // 3 (rows) System.out.println(matrix[0].length); // 3 (columns in row 0) // ── Nested loop traversal ───────────────────────────────────────── for (int row = 0; row < matrix.length; row++) { for (int col = 0; col < matrix[row].length; col++) { System.out.print(matrix[row][col] + " "); } System.out.println(); // new line after each row } // Output: // 1 2 3 // 4 5 6 // 7 8 9

📌 Classes, Objects, Constructors & Encapsulation
Student.java /** * Represents a student in the system. * Demonstrates encapsulation, constructors, and methods. */ public class Student { // ── Fields (private = encapsulated) ────────────────────────── private String name; private int studentId; private double gpa; // ── Constructor: called with 'new Student(...)' ─────────────── public Student(String name, int studentId, double gpa) { this.name = name; // 'this' refers to the current object this.studentId = studentId; this.gpa = gpa; } // ── No-argument (default) constructor ──────────────────────── public Student() { this("Unknown", 0, 0.0); // delegates to parameterised constructor } // ── Getters (accessor methods) ──────────────────────────────── public String getName() { return name; } public int getStudentId() { return studentId; } public double getGpa() { return gpa; } // ── Setter (mutator method) ─────────────────────────────────── public void setGpa(double gpa) { if (gpa >= 0.0 && gpa <= 4.0) { this.gpa = gpa; // validation before setting } } // ── toString: returns a String representation of the object ── @Override public String toString() { return "Student[" + name + ", ID:" + studentId + ", GPA:" + gpa + "]"; } }
Main.java — Using the Student class public class Main { public static void main(String[] args) { // Instantiate objects using 'new' Student s1 = new Student("Alice", 1001, 3.8); Student s2 = new Student(); // uses no-arg constructor System.out.println(s1.getName()); // Alice System.out.println(s1); // calls toString() // Output: Student[Alice, ID:1001, GPA:3.8] s1.setGpa(5.0); // rejected — validation fails (5.0 > 4.0) s1.setGpa(3.9); // accepted System.out.println(s1.getGpa()); // 3.9 } }

📄 Javadoc — Documentation Standards
📌 Writing & Generating Javadoc in JGrasp
📄 What is Javadoc?
Javadoc is Java's official documentation system. It reads specially formatted /** ... */ comments and generates professional HTML documentation pages (similar to the official Java API docs). In JGrasp, you can generate Javadoc via Tools → Javadoc. Well-documented code is a professional requirement — not optional.
Javadoc Example /** * Calculates the area of a rectangle. * * <p>Both dimensions must be positive. If either value is * negative or zero, the method returns -1 as an error indicator.</p> * * @param length the length of the rectangle in centimetres (must be > 0) * @param width the width of the rectangle in centimetres (must be > 0) * @return the area in square centimetres, or -1 if inputs are invalid * @author J. Smith * @version 1.0 * @since 2024 */ public static double calculateArea(double length, double width) { if (length <= 0 || width <= 0) return -1; return length * width; }
Javadoc TagPurposeExample
@param Describes a method parameter @param length the length value
@return Describes the return value @return the computed area
@throws Documents exceptions the method may throw @throws IllegalArgumentException if input negative
@author Names the author of the class/method @author J. Smith
@version States the version of the code @version 2.1
@since States when the feature was introduced @since 2024
@see References related classes or methods @see Math#sqrt(double)
@deprecated Marks code as outdated and not recommended for use @deprecated Use newMethod() instead
📌 JGrasp Javadoc Generation: In JGrasp, go to Tools → Javadoc. You can configure the output directory and choose which files to document. The result is a set of linked HTML files — open index.html in a browser to view the generated documentation. Note: Javadoc comments use /** (double star) — regular multi-line comments /* are NOT processed by the Javadoc tool.

📝 Section E — Extended Answer Questions 6 marks each = 18 marks Extended
E1
Extended Answer 6 marks
A learner writes the following Java program in JGrasp. The program compiles successfully but produces incorrect output.
GradeCalculator.java public class GradeCalculator { public static double calculateAverage(int[] scores) { int total = 0; for (int i = 0; i <= scores.length; i++) { // Line 5 total += scores[i]; } return total / scores.length; // Line 8 } public static void main(String[] args) { int[] marks = {70, 80, 90}; System.out.println(calculateAverage(marks)); } }

(a) Identify and explain ALL errors in this program.
(b) Rewrite the corrected method.
(c) Explain how you would use the JGrasp debugger to locate these errors step by step.
Words: 0
📋 Marking Guide (6 marks):
• 1 mark — Error 1 identified: Loop condition i <= scores.length should be i < scores.length — causes ArrayIndexOutOfBoundsException (runtime error) when i equals scores.length (index 3 in a size-3 array)
• 1 mark — Error 2 identified: total / scores.length performs integer division (both int values) — result is truncated. Should be (double) total / scores.length or total / (double) scores.length
• 1 mark — Corrected method written with BOTH fixes applied and compiling correctly
• 1 mark — Debugger strategy: set breakpoint on Line 5, use Step Over each iteration to watch i and total
• 1 mark — Mentions using Watch Expression to monitor i and spot when it reaches scores.length
• 1 mark — Mentions that integer division issue requires watching the return value of Line 8 and comparing against expected result
👁️ View Model Answer

(a) Errors:

Error 1 — Off-by-one in loop condition (Runtime Error):
Line 5: i <= scores.length should be i < scores.length. Array indices run from 0 to length-1. When i equals scores.length (3), scores[3] does not exist → throws ArrayIndexOutOfBoundsException.

(a) Definition:

Encapsulation is the OOP principle of bundling an object's data (fields) and behaviour (methods) into a single unit (a class), and restricting direct external access to the data by declaring fields private. Access is provided only through controlled public methods (getters and setters), which can validate inputs before modifying the object's state. This protects the integrity of data and makes code easier to maintain.

(b) BankAccount Example:

public class BankAccount { private String owner; private double balance; public BankAccount(String owner, double initialBalance) { this.owner = owner; this.balance = (initialBalance >= 0) ? initialBalance : 0.0; } public double getBalance() { return balance; } public String getOwner() { return owner; } public void deposit(double amount) { if (amount > 0) { balance += amount; } else { System.out.println("Invalid deposit amount."); } } public void withdraw(double amount) { if (amount > 0 && amount <= balance) { balance -= amount; } else { System.out.println("Invalid or insufficient funds."); } } @Override public String toString() { return "BankAccount[" + owner + ", balance=R" + balance + "]"; } }

(c) Risks Without Encapsulation:

If balance were declared public, any external code could write:

BankAccount acc = new BankAccount("Alice", 1000.0); acc.balance = -99999; // No validation — corrupts the object state!

This bypasses all validation, allowing the balance to be set to an impossible negative value. With encapsulation, this is prevented because balance is private and can only be modified through the validated deposit() and withdraw() methods.
