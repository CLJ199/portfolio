Overview
What is Computational Thinking?
🧩 Definition & The Four Pillars
💡
Computational Thinking (CT)
A problem-solving approach that involves breaking down complex problems into manageable parts and expressing their solutions in ways that a computer — or a human — can effectively carry out. It was popularised by computer scientist Jeannette Wing in 2006.
🔑 Key Idea: CT is NOT just about coding — it's a way of thinking applicable to everyday life.
Pillar One-Line Definition Key Question it Answers
🔧 Decomposition Breaking a complex problem into smaller, manageable sub-problems What are the parts of this problem?
🔍 Pattern Recognition Identifying similarities, trends, and regularities in data or problems What patterns or similarities exist?
🧠 Abstraction Focusing on essential information and ignoring irrelevant detail What details can be removed?
📊 Algorithms Designing a clear, step-by-step solution to a problem What are the exact steps to solve it?
📌 Remember: All four pillars work together. In practice, you may decompose a problem first, then spot patterns, abstract away unnecessary detail, and finally design an algorithm for the solution.
Pillar 1
🔧 Decomposition
📌 Definition, Purpose & Examples
🔧 What is Decomposition?
Decomposition is the process of breaking down a large, complex problem into smaller, more manageable sub-problems or tasks. Each smaller part is easier to understand, solve, and manage independently. Once all parts are solved, the solutions are combined to address the original problem.
💡 Why it matters: A problem that is too large or complex to tackle all at once becomes solvable when split into smaller components. It also allows different people (or systems) to work on different parts simultaneously.
EX 1
Real-World Example: Building a Website
Decomposed into:
→ Design the layout  |  Write the HTML  |  Add CSS styling  |  Write JavaScript  |  Set up a database  |  Deploy to a server
EX 2
Real-World Example: Making a Cup of Tea
Decomposed into:
→ Boil water  |  Get a mug  |  Add teabag  |  Pour water  |  Wait  |  Remove teabag  |  Add milk/sugar
EX 3
Computing Example: A Search Engine
Decomposed into:
→ Crawl web pages  |  Index content  |  Rank results  |  Handle user queries  |  Display results  |  Update the index
🔑 Each sub-task can be independently designed and improved.
📌 Key Terms: Sub-problem · Sub-task · Modular design · Divide and conquer · Top-down design
Pillar 2
🔍 Pattern Recognition
📌 Definition, Purpose & Examples
🔍 What is Pattern Recognition?
Pattern Recognition involves finding similarities, trends, repetitions, or regularities within and between problems. Identifying patterns allows us to apply previous solutions to new problems that share similar characteristics, making problem-solving faster and more efficient.
💡 Why it matters: If we can identify a pattern, we can write a single rule or algorithm that handles many different cases — rather than writing a separate solution for each individual case.
EX 1
Example: Spam Email Detection
Patterns identified in spam emails: certain keywords ("win", "free", "click now"), unknown senders, unusual sending times → A filter is built based on these patterns.
EX 2
Example: Weather Forecasting
Meteorologists identify patterns in temperature, pressure, and wind direction over time to predict future weather conditions.
EX 3
Example: Drawing Shapes (Programming)
Drawing a triangle, square, pentagon… all follow a pattern: repeat (draw a line → turn). The number of sides changes; the pattern stays the same.
🔑 This allows the use of loops in programming instead of repeating code.
Pattern Type Description Example
Similarities Features shared across problems All login pages need username + password
Differences Variations that require different handling Admin vs. regular user permissions
Trends Changes over time or datasets Sales increasing every December
Repetition A sequence that repeats consistently A timer counting down every second
Pillar 3
🧠 Abstraction
📌 Definition, Levels & Examples
🧠 What is Abstraction?
Abstraction involves identifying and focusing only on the essential details of a problem while removing (hiding) unnecessary or irrelevant information. It creates a simplified model of a complex system. Abstraction can be applied at many levels — from a high-level concept down to specific implementation details.
💡 Key Distinction: Abstraction is NOT about ignoring detail altogether — it's about knowing which details are relevant for a specific purpose and filtering out the rest.
EX 1
Example: A Map
A map is an abstraction of the real world. It keeps roads, landmarks, and distances but removes trees, building colours, and irrelevant detail. Different map types (transport map, weather map) abstract different relevant information.
EX 2
Example: A Car's Steering Wheel
A driver uses a steering wheel without knowing the mechanical details of how it connects to the wheels. The complexity is abstracted away — the driver only needs to interact with the simplified interface.
🔑 This is called information hiding — a core principle of software design.
EX 3
Example: Object-Oriented Programming (OOP)
A Dog class abstracts real dogs. It keeps relevant attributes (name, breed, age) and behaviours (bark(), eat(), sleep()) while ignoring irrelevant biological detail (cell structure, DNA).
Concept Description
Data Abstraction Representing data at a high level (e.g., a variable instead of a memory address)
Procedural Abstraction Using a function/method without knowing its internal implementation
Information Hiding Concealing internal workings; only exposing necessary interfaces
Generalisation Creating a general solution that works for many specific cases
Pillar 4
📊 Algorithms
📌 Definition, Properties & Types
📊 What is an Algorithm?
An algorithm is a precise, ordered sequence of steps or instructions designed to solve a problem or accomplish a task. Algorithms must be unambiguous, finite, and produce a correct output for valid inputs. They can be expressed as pseudocode, flowcharts, or actual programming code.
💡 Remember: An algorithm must eventually stop (it must be finite) and must produce the correct result every time it is run with valid inputs.
✅ Five Key Properties of a Good Algorithm
P1
Clearly Defined Inputs
The algorithm must specify what data/information it requires to start.
P2
Clearly Defined Outputs
The algorithm must produce at least one result or output.
P3
Unambiguous Steps
Each instruction must be clear and not open to interpretation.
💡 "Add something to the list" is ambiguous. "Append value X to array A" is not.
P4
Finiteness
The algorithm must terminate after a finite number of steps — it cannot run forever.
P5
Effectiveness
Each step must be basic and feasible — capable of being performed exactly and in a finite amount of time.
Algorithm Type What it does Example
Sorting Arranges data in a specific order Bubble Sort, Merge Sort, Quick Sort
Searching Finds a specific item in a dataset Linear Search, Binary Search
Pathfinding Finds the best route between two points Dijkstra's Algorithm, A* Algorithm
Encryption Converts data into a secure, unreadable format AES, RSA
Compression Reduces file size Huffman Coding, DEFLATE
Component 5
✅ Evaluation
📌 Why Evaluation Matters
✅ What is Evaluation in Computational Thinking?
Evaluation is the process of assessing a solution or algorithm to determine how well it works, whether it meets requirements, and how it could be improved. A good computational thinker doesn't just create a solution — they critically assess it.
🔎 Key Evaluation Criteria
C1
Correctness
Does the solution produce the right output for all valid inputs? Does it handle edge cases?
💡 Test with normal inputs, boundary values, and invalid inputs.
C2
Efficiency
Does the solution use minimal time and memory? This is measured using Big O notation (e.g., O(n), O(n²), O(log n)).
C3
Usability
Is the solution easy to use and understand by the intended users?
C4
Maintainability
Can the solution be easily updated, modified, or extended in the future?
💡 Clear code, good documentation, and modular design improve maintainability.
C5
Scalability
Does the solution still work well if the size of the problem grows significantly?
📌 Evaluation Tip: When asked to evaluate an algorithm in an exam, consider: correctness → efficiency → usability → maintainability → scalability. Use specific examples and evidence to support your points.

• 1 mark — Pattern Recognition: identifying common features across modules (e.g., all modules need login, search, add, edit, delete functions)
• 1 mark — Abstraction: hiding unnecessary detail from users (e.g., teachers see only relevant student data; database structure is hidden)

👁️ View Model Answer

🔧 Decomposition:
The student management system would be broken into smaller sub-systems: (1) Student Records module, (2) Attendance Tracking module, (3) Grade Management module, (4) Timetabling module, and (5) Reporting module. Each sub-system can be designed, built, and tested independently.

🔍 Pattern Recognition:
Across all five modules, a common pattern emerges — every module requires the same core operations: login/authentication, search, add a record, edit a record, and delete a record. This pattern means we can create reusable components and templates rather than building each function from scratch.

🧠 Abstraction:
Teachers are shown only relevant student data for their class — they do not need to see the underlying database schema, server configuration, or other students' sensitive data. The database complexity is abstracted away behind a clean user interface. Only the system administrator interacts with lower-level settings.

This is unambiguous, finite, and produces a consistent output.

Short Answer 5 marks
Explain the difference between Abstraction and Decomposition. Why is it important NOT to confuse the two? Use an original real-world scenario (NOT from the study notes) to illustrate BOTH concepts clearly.
Words: 0
📋 Marking Guide (5 marks):
• 1 mark — Correct definition of Decomposition with key distinction (breaking into parts)
• 1 mark — Correct definition of Abstraction with key distinction (filtering relevant from irrelevant detail)
• 1 mark — Clear explanation of why they are different and why the distinction matters
• 1 mark — Original real-world example correctly applying Decomposition
• 1 mark — Same or linked example correctly applying Abstraction
Note: Deduct 1 mark if the example used appears directly in the study notes.
👁️ View Model Answer

Decomposition is the process of breaking a large, complex problem into smaller, manageable sub-problems. Abstraction, on the other hand, is about identifying which details are essential for solving a problem and removing (hiding) those that are not. The key difference is: Decomposition asks "What are the parts?" while Abstraction asks "What details matter?"

Confusing the two is dangerous because applying the wrong technique leads to an incomplete solution. Decomposing when you need to abstract results in too much irrelevant detail; abstracting when you need to decompose results in failing to address all parts of the problem.

Real-World Example — Planning a Hospital:

Decomposition: Planning a hospital is broken into sub-systems — Emergency Department, Surgical Ward, Pharmacy, Radiology, Administration, and Catering. Each department is a sub-problem that can be planned and managed independently.

Abstraction: When designing the hospital's patient management app for nurses, only the patient name, ward, medication schedule, and vitals are shown. The underlying database structure, server IP addresses, billing information, and administrative records are abstracted away — irrelevant for a nurse performing their daily duties.

Short Answer 5 marks
Write a step-by-step algorithm in pseudocode for the following problem:

"A program should accept a list of 10 student scores (0–100), calculate the average score, identify the highest and lowest scores, and display whether the class average is a Pass (≥ 50) or Fail (< 50)."

Your algorithm must demonstrate: clearly defined inputs and outputs, use of a loop, use of selection (IF statement), and correct variable usage.
Lines: 0
📋 Marking Guide (5 marks):
• 1 mark — Inputs clearly defined (accepts 10 scores in a loop or array)
• 1 mark — Loop correctly used to iterate through the 10 scores and accumulate a total; highest and lowest correctly tracked
• 1 mark — Average correctly calculated (total ÷ 10)
• 1 mark — IF/ELSE selection correctly used to determine Pass or Fail (≥ 50)
• 1 mark — Outputs clearly defined (average, highest, lowest, Pass/Fail result displayed)
👁️ View Model Answer 
START

  // --- Inputs & Initialisation ---
  DECLARE scores[10]
  DECLARE total    ← 0
  DECLARE highest  ← 0
  DECLARE lowest   ← 100
  DECLARE average
  DECLARE result

  // --- Input Loop ---
  FOR i ← 1 TO 10 DO
    OUTPUT "Enter score for student " + i + ":"
    INPUT scores[i]

    total ← total + scores[i]

    IF scores[i] > highest THEN
      highest ← scores[i]
    END IF

    IF scores[i] < lowest THEN
      lowest ← scores[i]
    END IF

  END FOR

  // --- Calculate Average ---
  average ← total / 10

  // --- Selection: Pass or Fail ---
  IF average >= 50 THEN
    result ← "PASS"
  ELSE
    result ← "FAIL"
  END IF

  // --- Outputs ---
  OUTPUT "Class Average : " + average
  OUTPUT "Highest Score : " + highest
  OUTPUT "Lowest Score  : " + lowest
  OUTPUT "Class Result  : " + result

END
📌 Note: Accept any valid pseudocode style. The key requirements are: correct loop logic, correct accumulation, correct average calculation, correct IF/ELSE selection, and clearly labelled outputs. Syntax does not need to match any specific programming language exactly.
