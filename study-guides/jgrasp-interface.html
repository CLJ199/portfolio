Section 1
🖥️ What is JGrasp?
🖥️ JGrasp — A Lightweight Java IDE
JGrasp (Java Graphical Representation of Algorithms, Structures and Processes) is a lightweight Integrated Development Environment (IDE) developed at Auburn University. It is designed specifically for teaching and learning programming, particularly Java. JGrasp combines a source code editor, compiler, debugger, and unique visualisation tools — all in one application — making it ideal for beginners learning Java for the first time.
💡 Key distinction: JGrasp is not a word processor — it is a specialised tool for writing, compiling, debugging, and running Java programs. Every panel and button has a specific programming purpose.
📌 Core Purposes of JGrasp
①
Write Java source code
JGrasp provides a full-featured code editor with syntax highlighting, automatic indentation, and line numbering — making Java code easier to read and write correctly.
②
Compile Java programs
JGrasp uses the Java compiler (javac) to translate your .java source file into a .class bytecode file. Compilation errors (syntax mistakes) are reported in the compiler messages panel.
③
Run Java programs
After successful compilation, JGrasp launches the Java Virtual Machine (JVM) to execute your program. All output (from System.out.println) and keyboard input (from Scanner) appears in the I/O Window.
④
Debug and visualise programs
JGrasp includes a built-in debugger and unique visualisation tools such as the Control Structure Diagram (CSD) and Object Viewer to help learners understand how their code works step by step.

🗂️ Understanding the JGrasp Window
When you open JGrasp, the main window is divided into several key areas. Understanding what each area does is essential before you start coding. The interface is designed so that everything you need — writing, compiling, running, and debugging — is available without switching between separate applications.

Section 3
✏️ The Source Code Editor
📌 Editor Features
①
Syntax Highlighting
JGrasp automatically colours different parts of your Java code to make it easier to read. Keywords (like public, class, if) appear in one colour, String literals in another, and comments in another. This is called syntax highlighting.
💡 Syntax highlighting is visual only — it does not affect how the code runs.
②
Line Numbers
Line numbers are displayed in the left margin of the editor. They are essential for finding errors — when the compiler reports "error on line 7", you can immediately jump to that line. Line numbers are not part of your code.
③
Automatic Indentation
JGrasp automatically indents new lines inside { } blocks. Pressing Enter after an opening brace { will indent the cursor to the correct level. Proper indentation makes code significantly easier to read and debug.
④
Control Structure Diagram (CSD)
The CSD is drawn automatically in the left margin alongside your code. It draws bracket-like shapes around if blocks, for loops, while loops, and method bodies — making the structure of your program immediately visible without running it.
💡 The CSD is one of JGrasp's unique distinguishing features not found in most other IDEs.
⑤
Find & Replace
Access via Edit → Find/Replace or Ctrl + H. Allows you to search for any text in your file and optionally replace it with different text — useful when renaming variables throughout a large program.
⑥
Undo / Redo
Ctrl + Z undoes your last action. Ctrl + Y redoes it. JGrasp keeps a full history of changes so you can safely experiment and undo mistakes.

Section 5
▶️ Compiling & Running a Java Program in JGrasp
📌 Step-by-Step: Your First Program in JGrasp
  • Open JGrasp. Go to File → New to create a new file.
  • Type your Java code in the editor. The filename must match the class name exactly (e.g., HelloWorld.java for a class named HelloWorld).
  • Go to File → Save (or press Ctrl+S) to save the file.
  • Click the Compile button (🔨) or press Build → Compile. Watch the Compiler Messages panel at the bottom.
  • If there are no errors, the message "Compilation Successful" (or similar) appears. If there are errors, they are listed with line numbers — fix them and recompile.
  • Click the Run button (▶️) or press Build → Run. The I/O Window opens and your program's output appears.
  • If your program uses Scanner for input, type in the I/O Window and press Enter when prompted.
HelloWorld.java public class HelloWorld { public static void main(String[] args) { System.out.println("Hello, JGrasp!"); } } // After compiling and running, the I/O Window displays: // Hello, JGrasp!
📌 Understanding Compiler Messages

error: ';' expected A semicolon is missing at the end of a statement Go to the reported line number and add the semicolon
error: cannot find symbol A variable or method name is misspelled or not declared Check spelling and ensure the variable has been declared
class HelloWorld is public, should be in a file named HelloWorld.java The filename does not match the class name Rename the file to exactly match the class name (case-sensitive)
warning The code will still compile but may have potential issues Review the warning — it may indicate a potential bug
Section 6
📁 File Management in JGrasp
📌 Working with Java Files
①
File Extensions — .java vs .class
.java — The source file you write and edit. This is human-readable Java code.
.class — The compiled bytecode file created by javac. This is what the JVM actually runs. You never edit this file directly.
💡 You write .java files. JGrasp creates .class files automatically when you compile.
②
Naming Rules — Critical!
The filename must exactly match the public class name inside the file, including capitalisation. Java is case-sensitive.

✅ Class named StudentGrades → File must be saved as StudentGrades.java
❌ studentgrades.java or Student_Grades.java will cause a compiler error.
③
Opening Existing Files
Use File → Open to navigate to an existing .java file on your computer and open it in the editor. JGrasp can have multiple files open simultaneously — each appears as a tab in the editor or in the Project Manager panel.
④
Saving Files
Always save using File → Save or Ctrl+S before compiling. JGrasp may show an asterisk (*) in the title bar to indicate unsaved changes. Compiling an unsaved file will compile the previously saved version, not your latest edits.
⚠️ Unsaved changes = the compiler does not see your latest code!
⑤
Print & Export
Use File → Print to print your source code with syntax highlighting preserved. JGrasp also supports printing the CSD diagram alongside your code — useful for submitting assignments that require a visual structure diagram.

⚙️ JGrasp Settings & Customisation
📌 Useful Settings for Beginners

📌 Recommended for Beginners: Keep the default settings when starting out. The default font size, tab width (4 spaces), CSD visible, and line numbers visible are all ideal for learning. Only adjust settings if something is visually uncomfortable.

E1
Short Answer 5 marks
A beginner learner opens JGrasp for the first time, types the following program, and clicks the Run button immediately — without saving or compiling first.
FirstProgram.java public class FirstProgram { public static void main(String[] args) { System.out.println("My first program!") } }

(a) Explain what will happen when the learner clicks Run without saving or compiling first.

(b) Identify the syntax error in the code above and explain how to fix it.

(c) Describe the correct step-by-step process the learner should follow to successfully run this program in JGrasp.
Words: 0
📋 Marking Guide (5 marks):
• 1 mark — (a) Without saving, the compiler would process the previously saved version (or no file exists if never saved), so the learner's new code would not run; without compiling, no up-to-date .class file exists to execute
• 1 mark — (b) Syntax error correctly identified: missing semicolon at the end of the System.out.println(...) statement on line 3
• 1 mark — (b) Fix clearly explained: add a semicolon ; after the closing parenthesis on that line
• 1 mark — (c) Steps include: fix the error → Save the file (Ctrl+S or File → Save) → Compile (Build → Compile or 🔨 button)
• 1 mark — (c) Steps continue: check Compiler Messages for success → click Run (▶️) → observe output "My first program!" in the I/O Window
👁️ View Model Answer

(a) What happens when Run is clicked without saving or compiling:

If the file has never been saved, there is no .java file on disk and no .class file to run — JGrasp will produce an error. Even if the file was previously saved, clicking Run without compiling first means the JVM would attempt to run an old or non-existent .class file — not the learner's latest code. The new code would never execute.

(b) Syntax Error Identified and Fixed:

The syntax error is a missing semicolon at the end of the System.out.println("My first program!") statement. Every Java statement must end with a semicolon ;.

// BEFORE (error): System.out.println("My first program!") // AFTER (fixed): System.out.println("My first program!");

(c) Correct Step-by-Step Process:

  1. Fix the syntax error — add the missing semicolon after the println statement.
  2. Save the file using File → Save or Ctrl+S. Ensure the filename is FirstProgram.java to match the class name.
  3. Click the Compile button (🔨) or use Build → Compile. Watch the Compiler Messages panel.
  4. Confirm the Compiler Messages panel shows a success message (no errors). A FirstProgram.class file is now created.
  5. Click the Run button (▶️) or use Build → Run. The I/O Window opens and displays: My first program!

Answer ALL parts of the following question about the JGrasp interface:

(a) Name and describe the purpose of three different panels found in the JGrasp interface.

(b) Explain why the CSD (Control Structure Diagram) is considered one of JGrasp's most unique and valuable features for beginner programmers.

(c) A learner wants to change the font size of the editor to make code easier to read. Describe the exact steps they should follow in JGrasp to do this.

📋 Marking Guide (5 marks):
• 1 mark — (a) First panel correctly named with accurate description of its purpose (any from: Source Editor, I/O Window, CSD Panel, Compiler Messages, Project Manager, Debug Tab, Toolbar)
• 1 mark — (a) Second and third panels correctly named and described (award 1 mark for both being correct)
• 1 mark — (b) Explanation addresses that the CSD visually shows program structure (loops, if-blocks, method bodies) as bracket-like shapes alongside the code — without needing to run the program — helping beginners understand code flow at a glance
• 1 mark — (b) Explains that it is unique to JGrasp / not found in most other IDEs, and that it makes structural errors (e.g., missing braces, incorrectly nested loops) immediately visible
• 1 mark — (c) Correct steps: Settings → Editor → Font → change the font size value and apply
👁️ View Model Answer

(a) Three JGrasp Panels:

1. Source Editor — The central panel where you type your Java source code. It features syntax highlighting, line numbers, and automatic indentation to make writing code easier and more readable.

2. I/O Window — Located at the bottom of the JGrasp window. It displays all output produced by System.out.println when your program runs, and also accepts keyboard input when your program uses Scanner.

3. Compiler Messages Panel — Also at the bottom, in a separate tab from the I/O Window. After you compile, this panel lists any syntax errors found — with the line number, error type, and a brief description of each problem — so you can quickly find and fix them.

(b) Value of the CSD for Beginners:

The CSD is unique to JGrasp and is not found in most professional IDEs. It automatically draws bracket-like shapes in the left margin of the editor around every control structure — including if blocks, for loops, while loops, and method bodies. For beginners, this is invaluable because it makes the logical structure of the program immediately visible without needing to run the code. It helps learners spot structural mistakes such as missing closing braces, incorrectly nested loops, or if-blocks that are not where the programmer intended — all purely by looking at the diagram in the editor.

(c) Steps to Change Font Size:

  1. Click the Settings menu in the JGrasp menu bar.
  2. Select Editor from the dropdown.
  3. Click Font in the submenu.
  4. A dialog box opens — change the font size to the desired value (e.g., 14 or 16 for easier readability).
  5. Click OK or Apply to confirm. The editor text size updates immediately.
